# OpenGrid — working instructions for Claude Code

## What we are building

OpenGrid is a Rust web framework (Loco/Axum) whose application layer is
written in a strict PHP dialect (`.grd`, "OpenGrid dialect"). The dialect runs
on an embedded interpreter, a cleaned-up fork of `yingkitw/phprs` whose
original core has since been replaced by our own VM (`grd-vm`) and a
Cranelift JIT (`grd-jit`). The goal is Laravel's developer experience
(controllers, models, routes, facades) on a Rust core, with native Rust
classes for everything performance-critical (HTTP, database, sessions,
queues, mail, auth).

**All-in-one core:** interpreter and framework are one system. There is no
abstract host ABI and no second host. Whoever needs a capability in the
dialect writes the native function directly into the core. The only boundary
is a compile boundary: the interpreter core does not depend on
Tokio/Axum/SeaORM and stays testable in seconds (the Cargo feature `server`
adds the framework part).

No frontend for now: Inertia/Vue are deferred (UI1), controllers answer with
JSON.

## This repository

Everything lives in this repository; there is no outer workspace any more.
Documents are in `.agents/` (English; the German originals are kept
privately by the project lead and are not published).

```
<repo>/
├── CLAUDE.md                 this file
├── README.md, BENCHMARKS.md  public entry points (the README links the rest)
├── .agents/                  project documents (table below)
├── .devpod/                  Containerfile + compose.yml (Fedora, Rust, PHP reference, Claude Code, fish)
├── crates/vm/                grd-vm: parser (mago), compiler, bytecode, VM, builtins, native core classes; #![forbid(unsafe_code)]
├── crates/jit/               grd-jit: Cranelift JIT (tiers, background compiler); the only crate with unsafe (D6); binary `grd run|compile|parse|dump <file>`
├── crates/framework/         opengrid-framework: Loco hooks, worker pool, routing, request/response, middleware,
│                             validation, sessions, SQLite/SurrealDB layer (native/database/), dialect preludes (*.grd); binary `opengrid`
├── crates/pkg/               opengrid-pkg: module manager (modules from Git)
├── crates/*/tests/           one integration test binary per crate: tests/suite.rs + tests/suite/*.rs
├── examples/test-app/        the base application (modules auth, notes, benchsql); acceptance test examples/test-app/tests/api.sh
├── bench/                    the benchmark: run_all.sh (stages), framework/ (bm2.py and the other tools), frameworks/ (runtimes,
│                             setup and start of the comparison apps), the comparison apps *-app/, results/ (published raw data)
├── tools/                    commit.sh, green.sh, tests_inventory.py, release.sh
└── target/                   Cargo's build directory (CARGO_TARGET_DIR is honoured), not committed
```

The Laravel comparison app is generated by `bench/framework/laravel/setup.sh`
into `../bench/laravel-app`, next to the repository (never inside it; it
contains a full Composer vendor tree).

Work happens inside the Podman container (`.devpod/compose.yml`), without an
IDE. Build rules: `cargo` with few parallel jobs (the container has 13 GB of
RAM; fat LTO of the framework binary leaves about 3 GB), sccache, no
`cargo fmt` over the whole tree.

## Where we stand

**`.agents/ROADMAP.md` is the single source for order and state** (work
packages with IDs, "waiting on the project lead", risks). `.agents/STATUS.md`
only names the IDs currently in progress and how to resume after an
interruption. Decisions with their reasons are in `.agents/DECISIONS.md`.
Order and scope change only with a DECISIONS entry; every progress report
names the changed roadmap rows.

Fixed guard rails (details in DECISIONS):
- Database embedded by default: `surrealkv://<project>/.opengrid/db` without configuration, a server through the URL or `SURREAL_DB_*` (D2, DB1). Raw SQL on SQLite through the same `DB` facade.
- Schema declarative; SurrealKit **embedded as a crate** (D4). SurrealDB and SurrealKit only as dependencies, never copy or fork their source.
- No service container and no service provider in the dialect; convention instead of registration (D1).
- One process: jobs, scheduler and tasks run in the server process, CLI tasks through `.opengrid/control.sock` (D5).
- `unsafe` only in the crate `grd-jit`, at documented places (D6).
- Benchmarks follow the fixed method (D11, BENCH3): every side with the same raw SQL on the same SQLite build, the same endpoints and byte-identical answers; every deviation of a comparison app from its framework's defaults is listed in `bench/frameworks/DEVIATIONS.md`.
- Strict types (D10): GRD021 and `ArithmeticError` are enforced, `/` yields float; `OpenGrid\Support` (Str, Arr, Collection) is written in the dialect and tested against Laravel's behaviour (`crates/vm/tests/support/`).
- JIT (D9): conservative. The extended JIT behind `GRD_ADVANCED_JIT` is paused, the framework workers run it only with `OPENGRID_JIT=on`, `GRD_JIT=0` is the emergency switch; every JIT step needs the green differential test (`crates/jit/tests/suite/fuzz.rs`). The next work packages are JITW1–JITW4 (JIT for framework code, translation at server start).

## Working rules

1. **Tests stay green.** Commit through `tools/commit.sh <msgfile> <paths…>`: it stages the paths, runs `tools/green.sh` (the whole suite with `OPENGRID_REQUIRE_ORACLES=1`: a missing `php`, Laravel vendor or `surreal` fails the run; the oracle kind `platform` is exempt unless the private reference implementation is present) and commits only when green. The hook `.githooks/pre-commit` enforces this for a plain `git commit` too (once per clone: `git config core.hooksPath .githooks`); it also rejects staged dependency and build directories (`node_modules`, `.venv`, `_build`, `deps`, `dist`, `vendor/bundle`, …). CI (`.github/workflows/suite.yml`) runs on every push to `main` with `OPENGRID_ORACLES_EXCEPT=platform`. New language features get a test under `tests/`; removed constructs a rejection test in `tests/dialect.rs`.
2. **PHP is the reference, not the template.** For semantic questions run `php -r` in the container and compare; deviate only where `.agents/DIALECT.md` §5 provides for it, and document it there.
3. **Dialect before compatibility.** Never re-add what DIALECT §4.2 forbids. No Composer, no `include`, no superglobals.
4. **Interpreter gaps you find** go into `.agents/KNOWN_ISSUES.md` at once (snippet, expected PHP output, place in the code), even if they are not fixed right away.
5. **Commits:** one topic per commit, the message describes the behaviour (not the files), the test count at the end ("Suite: N green"). Push only when the suite is green. No attribution or co-author lines in commit messages.
6. **Document tests (D17):** every new package records its tests and tools in `.agents/Tools.md` (id, what it checks, kind, oracle, how to start); a test without an entry does not count as finished. `python3 tools/tests_inventory.py --check .agents/Tools.md` must pass without gaps.
7. **Credentials** only through the environment, never on command lines; nothing personal in commits or network requests (neutral User-Agent `OpenGrid-research (+https://github.com/OpenGridSolutions/framework)`); no network or other load while a measurement runs.
8. Code, comments, documents and commit messages are in English.

## Useful commands

```sh
cargo test --workspace                              # all suites
cargo test -p grd-vm                                # the VM only
cargo run -q -p grd-jit --bin grd -- run file.grd   # a script on the VM, with JIT (GRD_JIT=0 off, GRD_JIT_LOG=1 log, GRD_JIT_HOT=n threshold)
cargo build --profile perf -p opengrid-framework --bin opengrid   # the framework binary as the benchmark measures it (fat LTO)
bench/run_all.sh --plan                             # the benchmark's stages and estimated duration
bench/run_all.sh --smoke --skip-build --runs 1      # every stage with short durations
python3 bench/framework/bm2.py --targets opengrid-embedded-core,laravel-frankenphp-core --endpoints list --conc 16 --duration 3 --warmup 1
php -r 'echo (int) "12abc";'                        # check PHP's reference behaviour
sccache --show-stats                                # compiler cache
```
